# LinVita

面向 iPhone / iPad 的实验性 PlayStation Vita 模拟器，基于 [Veeb](https://github.com/veebteam/Veeb) 和 [Vita3K](https://github.com/Vita3K/Vita3K)。本分支重点维护中文界面、触屏/手柄操作、JIT、退出与切换游戏，以及已遇到的兼容性问题。

**当前源码版本：0.1.15（build 16）。** 文档整理于 2026-11-11，游戏实测主要来自 2026-11-03 至 11-05。11-09 已验证 0.1.15 重新签名安装、游戏库、奖杯和 JIT 正常，但没有在当天重新测试各款游戏性能。下表保留每项结果对应的版本，不把旧版实测自动算作新版通过。

本仓库提供模拟器源码、构建脚本和测试，不附带游戏、游戏更新、DLC、Vita 固件、许可证、配对凭据或个人存档。当前没有在此仓库发布预签名 IPA；可按下文自行构建和签名。

## 环境与功能

| 项目 | 当前状态 |
| --- | --- |
| 目标系统 | iOS / iPadOS 26.0 及以上，ARM64；项目部署目标为 26.0 |
| 实测设备 | iPhone 17 Pro / Apple A19 Pro，iOS 26.5.1；其他设备未做相同回归 |
| CPU | Dynarmic，Vita ARM/Thumb 指令转换为 ARM64；真机游戏需要 JIT |
| 图形 | Vulkan 经 MoltenVK 转为 Metal |
| 界面 | 默认简体中文，可切换英文、葡萄牙语；游戏内部语言取决于游戏资源 |
| 输入 | 虚拟双摇杆与按键、前后触屏切换、实体手柄、原生文字输入 |
| 游戏库 | 图标、搜索、收藏、列表/网格、最近使用；名称读取游戏元数据 |
| 游戏设置 | 每款游戏的 JIT 缓存、CPU 优化、分辨率、异步管线等 |
| 退出 | Home → 退出游戏，等待线程和渲染资源清理完成再回游戏库 |
| 存档/奖杯 | 游戏内正常存档、奖杯读取与展示；无即时存档（save states） |
| iCloud | 上游相关代码保留；LinVita 测试包未配置 iCloud entitlement，不承诺云同步可用 |
| 其他平台 | 保留上游代码；本分支没有完成 macOS / Windows / Linux / Android 回归 |

JIT 就绪、出现标题画面、能移动、能够通关是不同验证阶段。本项目尚无完整通关认证，也不保证稳定满帧。

## 安装和第一次启动

### 1. 准备安装包和签名

1. 按[构建步骤](#从源码构建)生成 `LinVita-0.1.15-test.ipa`。
2. 使用支持开发者签名的侧载工具安装。构建脚本的 ad-hoc 签名只用于打包校验，不能直接作为 iPhone 安装签名。
3. Mac 上已验证的操作方式：连接并解锁 iPhone，在 AltServer 菜单栏图标上按住 **Option** 点击，选择 **Sideload .ipa…**，再选 IPA。参考 [AltServer 官方说明](https://faq.altstore.io/release-notes/altserver)。
4. 也有使用 iloader 2.4.1 覆盖安装/续签 0.1.15 成功的记录；不同签名工具、版本与 Apple 账号条件可能影响结果。
5. 按系统提示完成开发者模式、信任等必要设置。签名到期后需要重新签名。

升级前先在游戏内保存，并备份存档。覆盖安装时保持原 Apple ID / Team / 应用身份，避免把升级变成另一个沙盒中的全新应用；不要为升级先卸载现有 LinVita。侧载工具可能给 Bundle ID 附加后缀，实际安装标识应以手机为准。

### 2. 配置 StikDebug 与 JIT

本项目测试过 StikDebug 的 **Universal / `universal.js`** 启动方式，11-09 的续签检查使用 StikDebug 3.2.2。配对和 DDI 要求会随 iOS 与 StikDebug 更新，按照 [StikDebug 官方项目](https://github.com/StikDebug/StikDebug)和[集成说明](https://github.com/StikDebug/StikJIT/blob/main/INTEGRATION.md)完成准备。

1. 安装并完成 StikDebug 的配对设置。
2. 在 StikDebug 中选择 LinVita，使用 Universal 脚本启用 JIT；也可点击 LinVita 选项页中的“通过 StikDebug 启用 JIT”。
3. 回到 LinVita，确认 JIT 状态为就绪，再启动游戏。
4. 完全结束 LinVita 进程、系统回收应用或重新签名后，应重新检查 JIT。只打开游戏库并不能证明 JIT 已启用。

应用内跳转会读取当前签名后的 Bundle ID，不需要把某台设备的标识写进脚本。配对文件具有设备访问能力，应保存在本机，不要放进 GitHub 或公开问题单。

## 导入固件和游戏

### 固件

在“选项 → 系统与内容 → 导入内容”选择自行取得的 Vita 固件 PUP；补齐所需系统资源后，确认固件状态显示已安装。缺少系统模块或字体时，先排查固件完整性。

### 游戏

支持的导入入口包括 VPK、ZIP、PKG 和已解压的游戏目录；格式被识别不代表所有 dump 类型都能启动。

- 通过应用内“导入内容”选择文件，或使用“文件”App → “我的 iPhone → LinVita → imports”放入待安装内容。
- 已解压目录应包含 `sce_sys/param.sfo`、`eboot.bin` 及游戏资源；游戏编号由 SFO 的 `TITLE_ID` 决定。
- `.7z` / `.rar` 先在电脑上解压。不能只改扩展名来转换格式；曾遇到扩展名是 `.7z`、实际是 RAR5 的包。
- 以安装历史和错误报告判断结果；导入中断后重新选择原文件重试。
- `imports` 是暂存目录。每次处理结束后，暂存副本会被清理，失败记录保留；请把原始备份放在该目录之外。
- 加密 PKG / 内容所需的有效许可证必须由用户自行提供。缺少许可证的 DLC 不能通过复制文件变为可用内容。

安装后的常用位置，均相对于 LinVita 的 Documents 目录：

| 路径 | 内容 |
| --- | --- |
| `vita/ux0/app/<TITLE_ID>/` | 已安装游戏 |
| `vita/ux0/addcont/<TITLE_ID>/` | DLC；还需要正确元数据及许可证 |
| `vita/ux0/user/<用户编号>/savedata/` | 存档；备份时保留整个对应游戏目录 |
| `config/config.yml` | 全局配置 |
| `config/config/config_<TITLE_ID>.xml` | 单款游戏覆盖配置，以实际生成文件为准 |
| `imports/` | 导入暂存与导入记录 |
| `diagnostics/`、`logs/` | 诊断采样和运行日志 |

### 更新补丁

先安装本体，再通过安装入口处理对应地区/编号的更新，并从启动日志核对实际运行版本。**仅看到 `ux0/patch/<TITLE_ID>` 存在，不足以证明更新已生效。** 本分支曾发现《讨鬼传2》更新已复制到该目录，但运行的仍是 1.00；将更新按核心的安装流程合并到本体并核验可执行文件后，才确认 1.04 生效。

手工修复前备份会被覆盖的文件。不同地区版本、汉化版本与官方更新不能随意混用。

## 日常操作与设置

### 保存、退出和切换

先用游戏自己的保存功能存档，再按虚拟 **Home → 退出游戏**。等待返回游戏库后再启动下一款。切到后台只是暂停当前会话，完全关闭进程会丢失未保存进度。

0.1.15 调整了退出后的内存地址预留方式，目标是减少连续换游戏时的分配失败。它已通过主机生命周期测试；实机连续多款游戏切换仍需补充回归。如果仍出现启动失败，可保存并完整重开 LinVita，再由 StikDebug 启用 JIT。

### ○ / × 确认键

核心支持 Vita 系统确认键偏好。当前 LinVita 界面没有单独的全局 ○ / × 切换控件，可在完全退出应用后备份并编辑 `config/config.yml`：

```yaml
sys-button: 0  # ○ 确认；1 为 × 确认
```

重新打开应用生效。存在单款游戏覆盖配置时，也需检查其系统确认键字段。这个设置只影响读取 Vita 系统偏好的游戏或系统对话框，不会交换全部 ○ / × 输入；游戏固定的攻击、跳跃按键保持原定义。曾有《战神1》的汉化画面提示按 ○，但系统设置为 ×，实测按 × 可以继续。

### 中文名称与游戏语言

LinVita 的界面中文和游戏内部中文分开处理。游戏库显示名称来自游戏 SFO/元数据，导入一个外文版本并不会自动翻译全部标题或游戏文本。本地整理过的一批游戏已经人工统一了简体中文名称，这些修改后的商业游戏文件不随源码发布。修改名称时保留 `TITLE_ID`、内容编号和其他字段，并保留原 SFO 备份。

### 性能设置

首次测试保持 **JIT 缓存 Auto**、CPU 优化开启、原生 1× 分辨率；修改后重新启动该游戏。每次只改变一项，用同一存档、同一场景对比。

- 增大每线程 JIT 缓存可能减少重编译，也会减少能够同时运行的线程数量。
- 当前启动 JIT 总池为 512 MiB。《讨鬼传2》`PCSH00292` 的 Auto 配置为普通线程 4 MiB；0.1.14 起，`FrameStepLoop` 尝试使用 64 MiB，同时要求至少保留 128 MiB 给其他线程，空间不够时回退到 4 MiB。手动覆盖配置会影响这个自动策略。
- 0.1.11 曾把总池扩大到 1 GiB，随后多款游戏出现 `std::bad_alloc`；0.1.12 已恢复 512 MiB。不建议直接重复扩大总池的做法。
- CPU 正在大量编译时，降低渲染分辨率未必改善帧率。先判断 CPU、着色器编译、GPU 和温度因素，再调整。
- “性能浮层”的帧时间不是触控到显示的完整延迟；游戏画面是否持续更新也需要观察。

## 常见失败原因与处理

| 现象 / 日志 | 已知原因或排查方向 | 处理方案与验证边界 |
| --- | --- | --- |
| 游戏库能打开，游戏无法运行；JIT 未就绪 | 当前应用进程尚未获得可用 JIT，或上次授权已随进程结束 | 通过 StikDebug Universal 重新启动，检查 JIT 状态；仍失败时检查配对、DDI、签名与系统版本 |
| 切换游戏后黑屏，重开应用恢复 | 旧版退出只返回界面，或清理/重新初始化失败；不同情况需以日志区分 | 使用 Home → 退出游戏并等待完成；0.1.10 起等待完整清理，0.1.15 处理地址预留；失败时冷启动并记录前后两款游戏 |
| `mmap failed Cannot allocate memory`、`late initialization failed (memory/audio/ngs)` | 《伊苏8》案例中实际失败在 guest 内存预留，发生于游戏程序加载之前；总括提示不能证明是音频故障 | 完整重开应用可临时恢复。0.1.15 保留并清空原 guest 地址预留，避免每次换游戏重新寻找整块空间；真机重复切换仍待验证 |
| `JIT arena exhausted`，创建角色后黑屏 | 同时存在的游戏线程太多，每线程缓存占满 JIT 总池 | 对《讨鬼传2》保持 Auto 小缓存策略；核对日志实际缓存大小，不要直接给所有线程分配更大缓存 |
| `std::bad_alloc` / 多个游戏同时启动闪退 | 普通内存分配失败；0.1.11 扩大 JIT 池后曾复现，不能仅凭该异常确定是某种系统限额 | 采用 0.1.12 以后恢复的 512 MiB 总池策略；采集崩溃调用栈。单次调试器豁免内存上限曾未解决该问题 |
| 《讨鬼传2》先能动，之后长时间不出新画面，PC 落到 0 | 在该案例中确认 Dynarmic 缓存回收后，返回预测仍引用旧代码位置 | 0.1.13 清理失效的返回栈条目；回归用例从错误执行 118977 次恢复为预期 90000 次；该修复不等于帧率问题全部解决 |
| 有画面但很卡 | 可能是 JIT 重编译、图形管线编译、GPU、温度或游戏本身的兼容性 | 记录相同场景的帧时间、JIT 取指和线程栈；《讨鬼传2》已观测到 CPU 编译热点，0.1.14 加入专用线程缓存策略 |
| 《战神》合集菜单能进，选单作提示“游戏已结束” | iOS 未处理 `LoadExec`，或启动文件名大小写不匹配 | 0.1.9 实现应用内可执行文件切换；已知内容副本需要准确的 `GOW1.self` / `GOW2.self` 文件名。仅对已核对的副本修复，不要盲目重命名其他版本 |
| 《战神》特定 Vitamin 内容插件无法加载 | 内容格式、插件路径与核心支持不一致 | 实测使用过局部兼容副本；该副本和第三方插件未随源码发布。不能把这项处理当作所有 Vitamin / Mai 游戏的通用支持 |
| 画面提示 ○，按 ○ 无反应 | 提示图与系统确认键偏好不一致，或游戏固定按钮逻辑 | 先试实际虚拟 × / ○；按前文调整 `sys-button`。系统偏好不会对所有游戏做按键互换 |
| `Missing file` / 找不到 SELF / 资源缺失 | 可能是内容不完整、大小写问题、更新不匹配，也可能是游戏探测可选文件 | 对照原始包校验、检查 Title ID 与文件名；不要只因一条 Missing file 就重装所有内容，必须结合启动是否停止 |
| 更新目录已在，但日志仍显示旧版本 | 复制更新文件未经过本分支实际生效的安装流程 | 备份后通过更新安装流程处理，并核对启动日志中的版本和可执行文件；《讨鬼传2》已验证 1.04 的实际加载 |
| DLC 不出现 | 缺许可证、SFO、内容编号不匹配，或 dump 格式不受支持 | 检查合法内容与许可证。已知一批《讨鬼传2》DLC 缺各自许可证，未安装；不以空目录或复制成功作为有效安装依据 |
| 签名到期、应用无法打开 | 侧载签名失效，属于安装层问题 | 使用相同账号和应用身份重新签名覆盖安装，再检查 JIT；不要先卸载丢掉存档 |
| Vulkan 输出 `Metal does not support disabling primitive restart` | 驱动能力提示；在部分仍能运行的采样中也出现过 | 结合后续是否出帧、是否有其他致命错误判断，不能仅凭这一行断定启动失败根因 |

0.1.15 保留的是 **4 GiB 虚拟地址范围**。退出时用空匿名映射替换旧数据，物理页面被丢弃；这不表示退出后持续占用 4 GiB 物理 RAM。最终销毁仍释放地址范围。

## 从源码构建

### 准备

使用 macOS、完整 Xcode 及命令行工具、CMake 3.22+、Ninja、Python 3.12+、XcodeGen。首次构建需联网获取剩余依赖。当前本地成功构建记录使用 Xcode 16.1 / iPhoneOS SDK 18.1，并设置部署目标 26.0；这是既有实测组合，不代表所有 Xcode 版本都已验证。模拟器调试还要求匹配的 iOS Simulator runtime，不能用模拟器测试替代手机 JIT 验证。

```sh
git clone https://github.com/linxz-coder/LinVita.git
cd LinVita
brew install cmake ninja python xcodegen
xcodebuild -version
xcrun --sdk iphoneos --show-sdk-version
python3 --version
```

这个发布快照已将 `external/` 依赖源码纳入 Git，包括带本地修复的 Dynarmic。保留的 `.gitmodules` 记录上游来源，目前没有需要另外拉取的 gitlink；不要用上游依赖覆盖掉本分支的修改。

### 生成侧载 IPA

```sh
mkdir -p dist/ios
LINVITA_OUTPUT_DIR="$PWD/dist/ios" bash ./build-linvita.sh > dist/ios/build.log 2>&1
python3 tools/verify-linvita.py \
  --ipa dist/ios/LinVita-0.1.15-test.ipa \
  --build-log dist/ios/build.log \
  --report dist/ios/validation.json
```

构建过程依次编译 CMake iOS Release 核心、暂存 MoltenVK/核心、生成 Xcode 工程、构建 SwiftUI 应用、执行 ad-hoc 签名并打包。`LINVITA_JOBS=4` 可以减少并发；`LINVITA_TOOLS_DIR` 可指定额外工具目录，常规情况下也会从 `PATH` 查找工具。未设置输出目录时，脚本使用仓库父目录的 `artifacts/`。

校验脚本检查 IPA CRC、签名结构、ARM64 / iOS 平台、最低系统版本、核心 UUID 与本地编译结果一致等，不依赖维护者的设备日志或游戏文件，也不把打包通过写成游戏兼容性通过。

Xcode 工程由 `ios/Vita3K/project.yml` 生成。修改工程设置应编辑 YAML，然后重新执行 `ios/Vita3K/scripts/stage-core.sh device`。上游 `build-ios.sh`、[building.md](building.md) 和 [iOS 开发文档](ios/Vita3K/README.md)保留了另一套签名/iCloud 流程，阅读时注意与本 README 的 LinVita 包区分。

## 诊断与反馈

先保存进度。在应用的“诊断”或“诊断高级设置”查看运行状态，也可从文件共享导出对应文件。更深入的模式说明见 [DIAGNOSTICS.md](ios/Vita3K/DIAGNOSTICS.md)。

建议记录：

1. LinVita 版本/构建号、设备型号、iOS 版本和 JIT 是否就绪。
2. 游戏名称、Title ID、游戏版本、内容格式，以及是否使用了更新或汉化。
3. 冷启动是否正常；若仅切换后失败，写明上一款游戏和 Home 退出步骤。
4. 停在导入、标题菜单、读档、创建角色、过场还是实际战斗。
5. 从 `diagnostics/active.txt` 找到本次 capture，提供对应 `runtime.log`、必要的轮转日志和 `telemetry.jsonl` 摘要；闪退另提供经脱敏的崩溃栈。
6. 性能问题用同一存档/路线采样1～2分钟，记录温度状态、画面是否持续更新、帧时间及设置，避免只比较菜单 FPS。

分享前删除账号、设备 UDID、沙盒路径中的个人信息、配对资料和许可证；不要把完整游戏或存档当作默认附件。本仓库仅公开整理后的测试结论，不上传维护者的原始手机日志。
